# Локализация горячих данных (машинно-зависимая оптимизация)
# Сравнение: результаты 04-loop-fusion.txt (до) против 05 (после).
# Процессор: AMD Ryzen 9 9900X, 32 ГБ ОЗУ
# ОС: Windows 11
# Конфигурация: Release, x64
# Сценарий: HARD (8x16 = 128 врагов), 256 пуль в полёте, 600 кадров
# Запуск: главное меню -> клавиша B
#
# Ключевые изменения:
# 1) Структура Enemy: поля, которые читаются каждый кадр (x, y, alive,
#    width, height), вынесены в начало; поля пикирования и отрисовки
#    (diving, dive_step, dive_target_x, color, palette_idx) - в конец.
# 2) Структура Bullet: поля, участвующие в движении и проверке
#    столкновений (x, y, active, is_enemy, width, height), идут первыми.
# 3) Массивы enemies[] и bullets[] выровнены на 64 байта (начало
#    кэш-строки). palette_idx сохранён - он нужен батчингу отрисовки.
#
# МАШИННО-ЗАВИСИМАЯ ОПТИМИЗАЦИЯ:
# Процессор не берёт из памяти отдельный байт - он читает целую строку
# кэша (64 байта). Если горячие поля структуры разбросаны, один цикл
# трогает несколько строк кэша вместо одной. Порядок полей не меняет
# ни алгоритм, ни число операций - он меняет только то, сколько
# памяти приходит в процессор на одинаковую работу.
#
# Прогон 1:
#   OLD draw + no bands : update=0.0247 coll=0.0229 fill=0.0722 work=0.0969 ms
#   OLD draw + bands    : update=0.0162 coll=0.0146 fill=0.0722 work=0.0883 ms
#   NEW draw + no bands : update=0.0238 coll=0.0222 fill=0.0103 work=0.0341 ms
#   NEW draw + bands    : update=0.0163 coll=0.0147 fill=0.0101 work=0.0264 ms
#   speedup: batching=7.12x  broadphase=1.51x
#
# Прогон 2:
#   OLD draw + no bands : update=0.0253 coll=0.0234 fill=0.0749 work=0.1001 ms
#   OLD draw + bands    : update=0.0158 coll=0.0144 fill=0.0730 work=0.0889 ms
#   NEW draw + no bands : update=0.0238 coll=0.0222 fill=0.0104 work=0.0342 ms
#   NEW draw + bands    : update=0.0160 coll=0.0146 fill=0.0103 work=0.0263 ms
#   speedup: batching=7.28x  broadphase=1.53x
#
# Прогон 3:
#   OLD draw + no bands : update=0.0246 coll=0.0229 fill=0.0737 work=0.0983 ms
#   OLD draw + bands    : update=0.0152 coll=0.0137 fill=0.0734 work=0.0886 ms
#   NEW draw + no bands : update=0.0213 coll=0.0199 fill=0.0102 work=0.0316 ms
#   NEW draw + bands    : update=0.0155 coll=0.0140 fill=0.0105 work=0.0261 ms
#   speedup: batching=6.99x  broadphase=1.42x
#
# Среднее по прогонам, мс:
#
#                     update   coll    work
#   было (04)        0.0189   0.0168   0.0318   (NEW + bands)
#   стало (05)       0.0160   0.0145   0.0281
#   изменение         -15%     -14%     -12%
#
#   было (04)        0.0263   0.0243   0.1025   (OLD + no bands)
#   стало (05)       0.0249   0.0230   0.0990
#   изменение          -5%      -5%      -3%
#
# ВЫВОД: на реальном сценарии (новый код с broad-phase) работа кадра
# сократилась примерно на 12%, причём одинаково в update и coll -
# оба цикла читают одни и те же массивы Enemy и Bullet, поэтому
# выигрыш у них общий. На исходном коде выигрыш меньше, так как
# основное время там уходит на многократно большее число проверок.
# ЦЕНА: структура Enemy выросла с 36 до 40 байт (+11%), Bullet не изменился
# (20 байт). Причина роста - bool alive требует 3 байта добивки, чтобы
# следующий int лёг на границу 4 байт. Это осознанный компромисс: 4 байта
# памяти на врага (всего 1 КБ на 256 слотов) в обмен на меньшее число
# обращений к кэш-строкам в каждом кадре. При 128 живых врагах массив
# занимает 5120 байт и по-прежнему целиком помещается в L1-кэш (32-48 КБ).
