# Эксперимент: SSE2-векторизация движения пуль
# Сравнение: результаты 05-locality.txt (до) против 06 (после).
# Сценарий одинаковый: 128 врагов (HARD 8x16), 256 пуль, 600 кадров, 3 прогона.
#
# Что сделано:
# 1) Новый модуль simd.c / simd.h - векторизация update_bullets через
#    SSE2 intrinsics (<emmintrin.h>). MSVC x64 не поддерживает встроенный
#    ассемблер, поэтому используются intrinsics: компилятор превращает
#    _mm_add_epi32 в paddd, _mm_cmpgt_epi32 в pcmpgtd - тот же машинный
#    код, что и при ручном написании на ассемблере.
# 2) Активные пули разложены на две группы (свои / вражеские), чтобы
#    в одном блоке из 4 пуль было одно направление полёта.
# 3) Блок из 4 пуль: четыре y в один xmm-регистр, сложение одной
#    инструкцией paddd, проверка границы экрана одной инструкцией
#    pcmpgtd, результат выключает вышедшие за экран пули.
# 4) Хвост (менее 4 пуль) обрабатывается скалярно.
# 5) Флаг g_use_simd: 1 - векторизованная версия, 0 - исходная скалярная.
#
# Прогон 1:
#   NEW draw + bands : update=0.0170 coll=0.0151 fill=0.0103 work=0.0273 ms
#   OLD draw + no bands : update=0.0235 coll=0.0216 fill=0.0722 work=0.0957 ms
# Прогон 2:
#   NEW draw + bands : update=0.0161 coll=0.0143 fill=0.0101 work=0.0261 ms
#   OLD draw + no bands : update=0.0232 coll=0.0214 fill=0.0714 work=0.0946 ms
# Прогон 3:
#   NEW draw + bands : update=0.0176 coll=0.0156 fill=0.0110 work=0.0286 ms
#   OLD draw + no bands : update=0.0246 coll=0.0226 fill=0.0728 work=0.0974 ms
#
# Среднее по прогонам, мс:
#
#                      update   coll    work
#   было (05)         0.0159   0.0144   0.0263   (NEW + bands)
#   стало (06)        0.0169   0.0150   0.0273
#   изменение          +6%      +4%      +4%   (медленнее)
#
#   было (05)         0.0249   0.0230   0.0990   (OLD + no bands)
#   стало (06)        0.0238   0.0219   0.0959
#   изменение          -4%      -5%      -3%   (быстрее)
#
# ВЫВОД: прироста нет. UPDATE_BULLETS не зависит ни от bench_old_draw,
# ни от g_use_bands - он одинаков во всех четырёх строках, поэтому
# разница в пределах +/-5% по разным строкам означает шум измерения,
# а не эффект оптимизации. Векторизация движения пуль не окупилась.
#
# ПРИЧИНЫ (объяснение для отчёта):
# 1) Пули хранятся в массиве структур (AoS). Поля y соседних пуль
#    разнесены на sizeof(Bullet) = 16 байт, поэтому загрузить четыре
#    значения одной командой movdqu нельзя - _mm_setr_epi32 собирает
#    регистр из четырёх отдельных mov. Экономия на paddd (одна
#    инструкция вместо четырёх add) съедается сборкой регистра.
# 2) Дополнительный проход по 512 пулям для раскладывания по спискам
#    idx_own и idx_enemy.
# 3) update_bullets - только часть фазы update: рядом выполняются
#    update_enemies, восстановление убитых врагов и дозаполнение пуль,
#    которые не векторизуются. Даже 4-кратное ускорение одной функции
#    даёт немного.
#
# СЛЕДУЮЩИЙ ШАГ: перенести векторизацию на проверку столкновений
# и разложить данные врагов в непрерывные массивы (SoA): bx/by/bw/bh
# параллельно band_list. Тогда _mm_loadu_si128 читает четыре значения
# одной командой, и одно сравнение проверяет четырёх врагов за такт.
